## Phase Goal

**As a** solo owner, **I want to** run an Arabic RTL app on real phones with a sync-ready database and proven native integrations, **so that** feature work never rests on guesses.

<objective>
Build the dev-only spike screen (FND-09, D-08): one self-reporting row per integration, a tested runner that produces one SPIKE_RESULT line, manual rows for the Firebase, crash, sentinel and Google Sign-In checks (REL-01 on device), the widget update row and the from-widget banner.

Purpose: the phase is a spike; success is "every row passes on both phones in a development build and a release build". This plan makes each row a concrete check so plans 01-15 and 01-16 only build, install, read results and apply any needed D-09 fallback.
Output: spike constants, runner and tests, rows, spike screen, dev link on home, Arabic strings.

No package or app.json change. Uses the database from plan 01-11, telemetry module from plan 01-12, and pushSpikeWidget from plan 01-13.
</objective>
