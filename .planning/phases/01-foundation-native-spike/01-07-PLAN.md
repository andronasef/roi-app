## Phase Goal

**As a** solo owner, **I want to** run an Arabic RTL app on real phones with a sync-ready database and proven native integrations, **so that** feature work never rests on guesses.

<objective>
First native proof: link EAS, set up signing for both platforms, build one EAS development build per platform, install it on the owner's real iPhone and Android phone (both set to English), and drive every spike row to pass within the D-09 timebox. The owner then runs the rows only a human can do (Google Sign-In with their account, adding and tapping the home-screen widget) and picks the Scripture font (D-04).

Purpose: FND-09 and phase success criterion 2 require the native stack proven together on real devices before any feature work. FND-01 and FND-02 can only be proven on a phone (forced RTL on an English-language device, tashkeel rendering in the bundled fonts).
Output: installed development builds, a Metro log with passing SPIKE_RESULT lines for both platforms, the owner's manual-row results and font choice, and 01-07-SUMMARY.md with build ids, per-row results and any fallback taken.

Device work rules: when argent tools are available, load the matching argent skill before touching a physical phone or debugging a React Native build, and prefer argent tools over raw adb or xcrun (those are the fallback). Take tap targets from the element tree, never from screenshot pixels. Stop retrying a tap after two failures and re-run discovery. Do not stop simulator servers or a Metro the owner started.
</objective>
