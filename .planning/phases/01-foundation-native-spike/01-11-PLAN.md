## Phase Goal

**As a** solo owner, **I want to** run an Arabic RTL app on real phones with a sync-ready database and proven native integrations, **so that** feature work never rests on guesses.

<objective>
Finish the sync-ready on-device database: every Phase 1 user-data table built from syncCols() (FND-06, D-11, D-12), append-only event tables whose counts are COUNT queries and whose undo is a tombstone (FND-07, D-13), one baseline migration, and the fixture-DB migration harness (D-14).

Purpose: Phases 4 to 8 add features on top of these conventions and Drive sync (Phase 8) merges by id, updatedAt and tombstones; getting the row shape wrong later means a data migration on users' phones. This plan locks the shape while no installed database exists.
Output: schema with six tables, event helpers, schema guard test, events test, generated baseline migration, the v1 fixture and its migration test, all runnable under Node without a device.

Runs in parallel with plans 01-12 (telemetry) and 01-13 (widgets): no shared files. Tests run under real Node through Vitest (Pitfall 12); better-sqlite3 opens the same migration folder the app bundles.
</objective>
