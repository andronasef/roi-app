<decisions>
## Implementation Decisions

### Repo layout & tooling
- **D-01:** Monorepo (apps: mobile, backend, admin; `packages/shared`) using **bun workspaces** with the **isolated linker** (`linker = isolated`) so Tailwind 3 (mobile) and Tailwind 4 (admin) never hoist into each other. Verify in the spike that Metro and native autolinking resolve under isolated installs; if not, fall back to "pin + verify in CI". — **Reversibility:** costly — changing package manager/linker touches every workspace and lockfile.
- **D-02:** `packages/shared` is consumed as **source TypeScript, no build step** by mobile (Metro), backend (Nest) and admin (Vite). It must stay pure TS with no Node-only APIs.
- **D-03:** Test runner is **Vitest** (shared package, backend, admin, fixture-DB migration tests via better-sqlite3 in Node).

### Scripture type & look
- **D-04:** Scripture font is **decided in the spike**: bundle two candidates (e.g. Amiri vs Noto Naskh Arabic / Scheherazade New) on the torture-fixtures screen and pick after viewing on real phones.
- **D-05:** UI font (buttons, labels, prayer/gratitude text) is a clean sans: **IBM Plex Sans Arabic or Noto Sans Arabic**, distinct from Scripture's naskh.
- **D-06:** Scripture font size is a **5-step stepped slider**, stored in MMKV, applied through a context so all Scripture text scales together.
- **D-07:** Visual feel for theme tokens: **warm, calm, paper-like**; cream/ivory light mode, deep warm-charcoal dark mode, muted gold/olive accent. Phase 1 sets tokens only.

### Spike screen & fallbacks
- **D-08:** Dev-only **spike screen with live self-test rows** per integration (MMKV write+read, test crash, test analytics event, Google sign-in, widget update, Reanimated), showing pass/fail with error text. Gated/removed before release.
- **D-09:** **Timebox then fall back**: one focused attempt plus one retry with fixes on a real device; if still failing switch to the documented fallback (NativeWind→Uniwind, expo-widgets→@bacons/apple-targets, ts-fsrs 6→5.4.2, Tiptap markdown→hand-written serializer) and record the decision.
- **D-10:** **Torture-fixtures screen** uses real fully-voweled verses plus edge cases: `{الاسم}` token names, mixed Arabic/Latin/digits, alef/hamza/taa-marbuta variants, long lines, and a search box. The same fixtures feed unit tests.

### Schema & event conventions
- **D-11:** Client IDs are **UUIDv7** (time-ordered), generated by a small pure-TS function in the shared package. — **Reversibility:** one-way — IDs are baked into synced/backed-up user data.
- **D-12:** Timestamps (`createdAt`, `updatedAt`, `deletedAt`) are **integer epoch milliseconds, UTC**. Local-day logic (gratitude day, week starting Saturday) uses a separately stored local date where needed. — **Reversibility:** one-way — format is baked into device DBs and Drive merge.
- **D-13:** Events (prayed, review) live in **separate append-only tables** (e.g. prayer_events, review_events) with UUID + parent id + timestamp, never edited; counts are COUNT queries; undo writes a tombstone on the event; merge is a union by id.
- **D-14:** Migration test uses **a checked-in SQLite fixture per released schema version** with sample rows; the test copies it, runs all pending Drizzle migrations, and asserts data survives intact (Vitest + better-sqlite3). Add a new fixture with every published schema version.
