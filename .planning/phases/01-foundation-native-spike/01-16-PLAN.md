## Phase Goal

**As a** solo owner, **I want to** run an Arabic RTL app on real phones with a sync-ready database and proven native integrations, **so that** feature work never rests on guesses.

<objective>
Release half of the native proof: apply the owner's Scripture font choice, build one release build per platform (iOS through the EAS preview profile, Android locally with the owner's key.jks as in Meme-Creator), rerun every spike row on the real phones, send the Firebase test event, test crash and sentinel error from release builds (Crashlytics only reports from release builds, Pitfall 5), and write the decision note that settles every spike outcome and the Phase 9 dev-gating carry-over for later phases.

Purpose: phase success criterion 2 needs one development build and one release build proven per platform; Pitfall 14 (Drizzle migrations break only in release) and REL-01 (no personal text in crash reports) can only be shown on release builds.
Output: installed release builds, RELEASE_RESULT lines for both platforms, Firebase triggers sent, 01-SPIKE-DECISIONS.md, and end-of-phase human checks for the Firebase console and release-only manual rows.

Device work rules: when argent tools are available, load the matching argent skill before touching a physical phone, and prefer argent tools over raw adb or xcrun (those are the fallback). Take tap targets from the element tree, never from screenshot pixels. Stop retrying a tap after two failures and re-run discovery. Do not stop simulator servers or a Metro the owner started.
</objective>
