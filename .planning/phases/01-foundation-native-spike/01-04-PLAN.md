## Phase Goal

**As a** solo owner, **I want to** run an Arabic RTL app on real phones with a sync-ready database and proven native integrations, **so that** feature work never rests on guesses.

<objective>
Create the Expo SDK 58 app in `app/` with the owner's familiar Meme-Creator layout and wire its whole stack once: every dependency and every config plugin the phase needs (so plans 01-05 and 01-06 never touch package.json or app.json), forced RTL (FND-01), Drizzle migrations with one real settings write and read, NativeWind theme tokens with a light/dark switch (FND-05, D-07), bundled fonts with a 5-step Scripture size (FND-02, D-04, D-05, D-06), the dev-gated torture-fixtures screen with Arabic search (FND-03, FND-04, D-10), Reusables Dialog and Select, lint with accessibility rules, and the guard tests.

Purpose: this is the walking skeleton. Native compilation is first proven by the EAS builds in plan 01-07; this plan proves the JavaScript graph (bundles for both platforms) and, through expo prebuild, that every config plugin composes into the native projects.
Output: `app/` with app shell, home screen, torture screen, generated baseline migration, lint config and guard tests.

Layout inside app/ (mirrors the owner's Meme-Creator project): app/ (expo-router routes), components/ (Reusables UI), constants/ (every tunable value: app.ts, theme.ts; no module-scope literals in feature files), features/NAME/, services/, hooks/, locales/ (Arabic UI strings), plugins/ (local config plugins), scripts/, drizzle/ with drizzle.config.ts, assets/, `__tests__/` folders next to the code. `@/*` path alias. app.json for static config plus app.config.js for dynamic config. Two deliberate differences from Meme-Creator, both from locked decisions: color tokens are NativeWind CSS variables in global.css (CLAUDE.md stack: NativeWind plus Reusables), and `main` is index.ts rather than expo-router/entry (plan 01-06 must register the Android widget handler before the router loads).
</objective>
