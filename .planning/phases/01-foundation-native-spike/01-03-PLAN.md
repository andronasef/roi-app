## Phase Goal

**As a** solo owner, **I want to** run an Arabic RTL app on real phones with a sync-ready database and proven native integrations, **so that** feature work never rests on guesses.

<objective>
Create the bun-workspace monorepo with the isolated linker (D-01) and the pure-TypeScript `@roi/shared` package consumed as source (D-02), tested with Vitest under real Node (D-03). This plan puts the Arabic part of shared in place: normalization and search (FND-04), Arabic-Indic digits and dates (FND-03), `personalize()`, and the torture fixtures (D-10) that the mobile screen in plan 01-10 and the unit tests share. Plan 01-04 adds ids, period keys, merge and schemas without touching any root file or the lockfile; plan 01-05 proves backend and admin consume `@roi/shared`.

Purpose: FND-08 says one shared package is imported by app, backend and admin; establishing the workspace root and pure-TS Arabic core first lets subsequent plans build sync primitives and workspace consumers cleanly without exceeding plan scope.

Layout: top-level sibling folders as in the owner's Meme-Creator project (app/, backend/, admin/, shared/), each a bun workspace; tests live in `__tests__/` folders next to the code they test. D-01 named the folders apps/* and packages/shared; only the names changed, the bun workspaces and isolated linker are kept.
Output: root workspace files, `shared/` Arabic module with tests, a committed `bun.lock` that already contains every root and shared package this phase needs (zod, vitest, typescript, uuid).

Runs in parallel with plan 01-02 (owner console setup). No device needed.
</objective>
