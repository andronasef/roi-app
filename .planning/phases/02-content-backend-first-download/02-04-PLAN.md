Create `app/features/sync/staging.ts` defining `StagingStore` interface (`readManifest()`, `writeStage(type, envelope)`, `readStage(type)`, `clear()`) and `createExpoStagingStore()` backed by `Directory`, `File`, and `Paths.document` from `expo-file-system` (`02-RESEARCH.md` Code Examples). Never use SQLite hard deletes or legacy `expo-file-system` APIs; ensure `writeStage` writes the stage JSON and updates `manifest.json` (`{ contentVersion, completed }`), and `clear()` deletes `content-staging` directory if it exists.

Create `app/features/sync/first-download.ts` exporting `readSyncState(db)` (reads `syncMeta` row `CONTENT_SYNC_META_ID`, returning `{ lastContentVersion, lastCheckedAt }` defaulting to `0, 0`), `readLibraryCounts(db)` (returns `{ verses, namesOfGod, blessings }` counts of rows with `deletedAt IS NULL`), and `runFirstDownload({ db, clock, api, staging, onProgress })` (implementing `D-02` and `HOME-07`):
1. Read `staging.readManifest()`. If manifest exists with `contentVersion > 0`, determine remaining stages in `CONTENT_STAGES` (`verses` -> `names_of_god` -> `blessings`).
2. Loop through remaining stages, calling `onProgress(stage, completedCount, totalCount)` before each fetch.
3. On each fetched snapshot: if `manifest` already holds a `contentVersion` and `fetched.contentVersion !== manifest.contentVersion`, call `await staging.clear()`, notify progress back to stage 1 (`verses`), and restart the batch cleanly from `verses` (`D-02`).
4. Otherwise persist via `await staging.writeStage(stage, fetched)`.
5. Once all 3 stages are staged at uniform `contentVersion`, read all 3 payloads and execute one synchronous `db.transaction((tx) => { ... })` upserting `verses`, `namesOfGod`, `blessings` (via `.onConflictDoUpdate`) and `syncMeta` (`lastContentVersion: V`, `lastCheckedAt: clock.now()`).
6. Only after `db.transaction` succeeds, call `await staging.clear()`. Never call `db.delete` or `tx.delete` (`schema.test.ts` compliance).

  <name>Task 3: Implement silent 6-hour throttled background delta sync with soft-delete tombstones (D-03, BE-02)</name>
  <files>app/features/sync/delta-sync.ts, app/features/sync/__tests__/delta-sync.test.ts</files>
  <behavior>
    - runDeltaSyncIfDue returns immediately without network calls when lastContentVersion === 0 (initial download not yet done) or when now - lastCheckedAt < DELTA_SYNC_THROTTLE_MS (6h) or when offline.
    - When lastContentVersion > 0, online, and >= 6 hours have elapsed since lastCheckedAt, queries contentDelta(lastContentVersion).
    - Inside one atomic db.transaction, upserts new and updated verses/namesOfGod/blessings and applies soft-delete tombstones (setting deletedAt and updatedAt) via onConflictDoUpdate without calling db.delete()/tx.delete(), then updates syncMeta.lastContentVersion and lastCheckedAt.
    - Network errors during silent delta sync fail quietly (returning { status: 'failed' } without throwing or erasing committed local data).
  </behavior>
  <action>
Create `app/features/sync/delta-sync.ts` exporting `runDeltaSyncIfDue({ db, clock, api, isOnline, throttleMs = DELTA_SYNC_THROTTLE_MS })`:
1. Read `syncMeta` row (`CONTENT_SYNC_META_ID`). If missing or `lastContentVersion === 0`, return `{ status: 'skipped', reason: 'not_initialized' }`.
2. If `!isOnline`, return `{ status: 'skipped', reason: 'offline' }`.
3. If `clock.now() - syncState.lastCheckedAt < throttleMs`, return `{ status: 'skipped', reason: 'throttled' }`.
4. Fetch `delta = await api.fetchContentDelta(syncState.lastContentVersion)` inside a `try/catch`; on network/validation failure, return `{ status: 'failed' }` silently without mutating `syncMeta.lastContentVersion` (`D-03`).
5. Execute one synchronous `db.transaction((tx) => { ... })`: if `delta.contentVersion > syncState.lastContentVersion`, upsert all `delta.verses`, `delta.namesOfGod`, and `delta.blessings` via `.onConflictDoUpdate` preserving `deletedAt` tombstones (never calling `tx.delete`), and update `syncMeta` (`lastContentVersion: delta.contentVersion`, `lastCheckedAt: clock.now()`). If `delta.contentVersion === syncState.lastContentVersion`, update only `syncMeta.lastCheckedAt: clock.now()`.

Write `app/features/sync/__tests__/delta-sync.test.ts` against migrated in-memory SQLite testing: skipped when `lastContentVersion === 0`; skipped within 6h (`5h 59m`) and executed at `>= 6h`; inserts new item, updates existing item, and soft-deletes tombstoned item (`deletedAt != null` excluded by `readLibraryCounts`); and silent failure leaves existing offline content and `lastContentVersion` intact.
