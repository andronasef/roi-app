## Phase Goal

**As a** new user, **I want to** download the app's content once from a reliable backend and then use it fully offline, **so that** I can use Ro'i anywhere.

<objective>
Stand up the NestJS 12 + Apollo Server 5 HTTP/GraphQL read API in `backend/`: `GET /snapshots/:type` serving pre-built gzipped snapshots (`BE-01`), `contentDelta(sinceVersion)` monotonic delta query with tombstones (`BE-02`), `GET /health` readiness endpoint (`BE-06`, `D-08`), and ApolloArmor / throttling / production GraphQL lock in `AppModule` (`BE-04`, `D-09`).

Purpose: Deliver the public read endpoints and GraphQL query hardening that the mobile first-download and delta-sync client consume, tested end-to-end with Supertest.
Output: NestJS modules, controllers, resolvers, `GqlThrottlerGuard`, and Supertest `content-api.test.ts`.
</objective>

  <behavior>
    - Booting AppModule loads pre-built .json.gz snapshots into memory (building them via rebuildAllSnapshots if missing on disk).
    - GET /snapshots/:type returns 200 with Content-Type application/json, ETag, X-Content-Version, Vary: Accept-Encoding, and Content-Encoding: gzip when Accept-Encoding includes gzip (or gunzipped JSON when gzip is absent), and 404/400 for invalid snapshot types.
    - GET /health executes SELECT 1 on SQLite and checks snapshot availability for verses, names_of_god, and blessings, returning 200 { ok: true, contentVersion, snapshotsReady: true } (or 503 if unavailable), bypassing rate throttling via @SkipThrottle().
  </behavior>
  <action>
Create `backend/src/db/drizzle.module.ts` as a `@Global()` Nest module providing `BACKEND_ENV` (via `useFactory: () => loadEnv()` so test env overrides are never cached at import time), `SQLITE_DB`, and `DRIZZLE_DB` (opening `openBackendDatabase(env.DATA_DIR, resolveBackendPath('drizzle'))` using `backend/src/config/paths.ts` so both ESM Vitest and `dist/*.cjs` resolve migrations cleanly, and closing SQLite in `OnModuleDestroy`).

Create `backend/src/content/snapshot.service.ts` (`@Injectable()`) implementing `OnModuleInit`: loads existing `.json.gz` buffers from `DATA_DIR/snapshots/` into an in-memory `Map<SnapshotType, { buffer: Buffer; etag: string; contentVersion: number }>`, or calls `rebuildAllSnapshots` from `snapshot-builder.ts` if any file is absent; exposes `getSnapshot(type)` and `refreshCache()` (called after writes/seed).

Create `backend/src/content/snapshot.controller.ts` (`GET /snapshots/:type`): validate `:type` with `snapshotTypeSchema` from `@roi/shared` (throwing `BadRequestException` if invalid), fetch from `SnapshotService.getSnapshot(type)`, set `ETag`, `Cache-Control: public, max-age=60`, `Vary: Accept-Encoding`, and `X-Content-Version`. Check `req.acceptsEncodings('gzip')`: when gzip is accepted send the pre-compressed `Buffer` directly with `Content-Type: application/json; charset=utf-8` and `Content-Encoding: gzip`; otherwise decompress with `zlib.gunzipSync` and send JSON (`02-RESEARCH.md` Pitfall 4).

Create `backend/src/health/health.controller.ts` (`GET /health` with `@SkipThrottle()` per D-08): probe SQLite with `SELECT 1`, read `content_meta.content_version`, verify `SnapshotService.areSnapshotsReady()`, and return `{ status: 'ok', contentVersion, snapshotsReady }` (or throw `ServiceUnavailableException` if DB or snapshots fail).

Create `backend/src/app.module.ts` wiring `ConfigModule.forRoot({ isGlobal: true })`, `ThrottlerModule.forRoot([{ name: 'default', ttl: 60_000, limit: 60 }])`, `DrizzleModule`, `SnapshotController`, `HealthController`, and `GraphQLModule.forRootAsync<ApolloDriverConfig>` (`driver: ApolloDriver`, `useFactory: () => ...`) so `const env = loadEnv(); const isProd = env.NODE_ENV === 'production';` and `new ApolloArmor(...)` are evaluated dynamically at module initialization time rather than cached at import time (ensuring Vitest tests that override `process.env.NODE_ENV = 'production'` in `hardening.test.ts` never suffer from stale import-time caching). [ApolloServerPluginLandingPageDisabled()] : [])]`.

  <behavior>
    - contentDelta(sinceVersion) rejects negative sinceVersion via Zod/validation and returns { contentVersion, verses, namesOfGod, blessings } containing ONLY rows where version > sinceVersion.
    - Soft-deleted rows (deletedAt != null) whose version > sinceVersion are included in contentDelta with deletedAt populated so clients apply tombstones (BE-02).
    - When sinceVersion >= current contentVersion, contentDelta returns empty arrays and current contentVersion.
    - GqlThrottlerGuard extracts Express req and res from GqlExecutionContext for GraphQL resolvers and throttles excessive requests with HTTP 429.
  </behavior>
  <action>

Register `GqlThrottlerGuard` as `APP_GUARD` in `AppModule`.

Create `backend/src/content/content.service.ts` (`@Injectable()`): implement `getCurrentVersion()`, `getContentDelta(sinceVersion: number)` querying `verses`, `namesOfGod`, and `blessings` where `gt(table.version, sinceVersion)` ordered by `asc(table.version), asc(table.id)` (including rows where `deletedAt !== null` so tombstones propagate per `BE-02`, parsing `tagsJson` back to `string[] | null`), and a reusable transactional helper `applyContentMutation(...)` (incrementing `content_meta.content_version`, inserting `audit_log`, and triggering `SnapshotService.refreshCache()` after commit — ready for Phase 3 admin mutations as well).

Register `GqlThrottlerGuard`, `ContentService`, and `ContentResolver` in `backend/src/app.module.ts`.
